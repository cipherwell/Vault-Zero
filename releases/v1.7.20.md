# 🛡️ VaultZero `v1.7.20` — interrupted-setup fix

**Release date:** 22 November 2026
**Package:** `com.cipherwell.vaultzero` · **versionCode:** 29
**Min SDK:** 24 · **Target/compile SDK:** 36 · **License:** MIT

Fixes a first-run bug where a vault could be created while its Recovery Kit was only in memory, so a
process death or lock left the user at a password prompt with no kit ever confirmed.

## Fixed

- **Pending-kit state is persisted atomically with the vault.** If setup is interrupted before
  “I Saved My Recovery Kit — Open Vault”, the next launch shows an amber notice on the unlock screen.
  After a correct Master Password or biometric unlock, the **same Recovery Kit is displayed again**
  before the vault opens. Confirming it clears the pending state.
- **Auto-lock can no longer interrupt setup.** Auto-lock is ignored unless the vault is unlocked,
  `clearVault()` cancels its pending timer, and resetting a vault can no longer leave a timer that
  fires into the setup wizard.
- **Keyboard “Done” no longer creates a vault.** The confirm field only hides the keyboard; creation
  requires the explicit **Create Secure Vault** button.

## Verification

- Reproduced on the emulator: setup → recovery kit → force-stop before confirming → relaunch shows the
  banner; unlock re-shows the kit; confirm opens the vault; next relaunch has no banner.
- **138 JVM/Robolectric tests / 0 failures** (new regression test: pending flag set at setup,
  decryptable with the active VMK, cleared only on confirmation), lint 0.
- Shipped APK: `versionCode 29`, `flags=0x0`, `screencap` 0 bytes.
