# 🛡️ VaultZero `v1.6.0` — Argon2id key derivation

**Release date:** 21 November 2026
**Package:** `com.cipherwell.vaultzero` · **versionCode:** 8
**Min SDK:** 24 (Android 7.0) · **Target/compile SDK:** 36 · **License:** MIT
**Source:** https://github.com/cipherwell/Vault-Zero
**Website:** https://cipherwell.github.io/Vault-Zero/

This release replaces PBKDF2-HMAC-SHA256 with **Argon2id** for every new password and
recovery-phrase key envelope. It closes the last open residual from the 2026-11-15 self-audit.

## 🔐 What changed

- **Argon2id (RFC 9106, version 1.3)** — 64 MiB memory, 3 iterations, 1 lane, 256-bit tag,
  128-bit random salt per envelope, pure-Java Bouncy Castle 1.87 (no native code, no ABI impact).
  The implementation is pinned to the RFC 9106 known-answer vector in the test suite.
- **Per-envelope KDF descriptors.** Each envelope now stores the exact KDF that wraps it
  (`argon2id:<mKiB>:<time>:<lanes>` or `pbkdf2-sha256:<iterations>`), so the password and recovery
  envelopes can never drift apart when one of them rotates, or when a vault is restored from an
  older backup.
- **Transparent migration.** A successful unlock of a PBKDF2 vault re-wraps both envelopes with
  fresh salts under Argon2id in one atomic preference commit. The vault master key and every
  encrypted record stay untouched — no re-encryption, no data migration step, no user action.
- **Backup format `3.3`** carries both KDF descriptors. `3.2` and older backups still import and
  are treated as PBKDF2 (verified on device with a real v1.5.0 backup). Import rejects unknown
  algorithms and out-of-range parameters before any derivation, so a crafted file cannot force a
  memory/CPU denial of service.

## ⚡ Performance

Measured on the API 34 `VaultZero-Live` emulator (ART, x86_64), same device, same password:

| KDF | Time |
| --- | ---: |
| Argon2id 64 MiB, t=3 (new) | **680–827 ms** |
| PBKDF2-HMAC-SHA256 600,000 (previous) | 2,809–3,062 ms |

Argon2id is both stronger against offline GPU/ASIC guessing **and** roughly 4× faster than the KDF
it replaces. Hardware biometric unlock is unchanged and still avoids the password KDF entirely.

## ⬆️ Upgrading

Existing vaults open with the same master password or 12-word recovery phrase and migrate in
place on that first unlock. Nothing to export, nothing to re-enter. Downgrading to 1.5.0 or older
after a migration is not supported (the old build cannot derive an Argon2id envelope).
