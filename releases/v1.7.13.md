# 🛡️ VaultZero `v1.7.13` — pre-beta security fixes

**Release date:** 21 November 2026
**Package:** `com.cipherwell.vaultzero` · **versionCode:** 22
**Min SDK:** 24 · **Target/compile SDK:** 36 · **License:** MIT

The full pre-beta audit and penetration test is in
[`docs/security/AUDIT-2026-11-21.md`](https://github.com/cipherwell/Vault-Zero/blob/main/docs/security/AUDIT-2026-11-21.md).
It found **no Critical/High** issues and **two Medium DoS bugs in the backup import path**, both
fixed here.

## Fixes

- **Bounded backup reads.** The importer called `readBytes()` and compared the size afterwards. A
  malicious or oversized document could allocate everything and OOM the process (`OutOfMemoryError`
  is an `Error`, so `catch (Exception)` never saw it). Reads now stop at the 8 MB ceiling.
- **Deep-JSON guard.** A 20,000-level nested backup threw `StackOverflowError` from `org.json`,
  escaping the import's exception handling and killing the app. Parsing now pre-scans nesting depth
  (64, string-aware) and maps overflow to `INVALID_JSON`.
- Six new regression tests cover both paths plus the repository-level import.
- The reusable audit kit lives in `security-audit/` (MASVS 2.1 methodology, scripts, checklists,
  fuzz corpus, report renderer).

## Audit coverage

Static review (manifest/components, crypto, storage, backup, UI/platform), on-device checks
(FLAG_SECURE, run-as, intents, logcat, clipboard policy), a debug-build storage inspection (no
plaintext in prefs/DB/WAL), 137 JVM/Robolectric tests, lint, and the instrumentation suite.

**Hardware verification (22 Nov 2026): 15/15 instrumentation tests pass on the Pixel 9 Pro XL
(Android 17), including all four biometric key-binding tests.** The emulator cannot create the
auth-required Keystore key (no secure lock screen/enrolment), which is why the hardware run matters.

  permission in the merged manifest.
